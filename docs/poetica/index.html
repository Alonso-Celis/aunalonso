AÚN

Aún quiere decir todavía: lo que no ha cesado. El archivo se llama así porque su asunto es la persistencia — tu voz que no cesa desde entonces — y porque un sitio de escritura debería comportarse como la memoria y no como una vitrina: acumular, borrar mal, dejar residuos.

Propuesta en una frase: un archivo de escrituras donde cada texto genera su propia forma por reglas públicas y deterministas. La forma no ilustra el texto. Lo lee. Y como la regla es pública, la obra se puede discutir, refutar y continuar — eso es lo que la separa del adorno generativo.

Las reglas

El sistema entero cabe en siete reglas. Están numeradas porque van a cambiar: la versión actual del cuaderno de reglas es R1, y cada obra nueva puede añadir o corregir una.

  1. El texto es la semilla. El dibujo se calcula a partir del texto mismo: un hash de sus letras alimenta el generador de azar. El mismo texto da siempre la misma imagen. No hay azar de sesión, no hay «regenerar hasta que quede bonito».
  2. La página es el dato. El dibujo no lee una base de datos ni un JSON: lee el DOM de la página que lo contiene. Si el texto cambia, la forma cambia. Si el texto desaparece, la forma desaparece. No hay dos verdades.
  3. Nada gira en bucle. El tiempo es material: cada obra se deposita durante unos treinta segundos y se detiene. Un bucle infinito es una promesa falsa de vida. Aquí lo que hay es sedimento.
  4. La negación borra, la adición deposita. La sintaxis manda sobre la forma. Una oración que niega se dibuja como sustracción; una que añade, como depósito. La tabla de correspondencias está más abajo y es la parte revisable del sistema.
  5. Una obra, un color. Negro de sala, hueso para la letra y un solo acento cromático por texto, tomado de su propia materia — en la obra 001, el púrpura del cabello. Dos acentos serían decoración.
  6. Dos lenguas, dos hermanas. El español y el inglés no son la misma obra traducida: cambian de semilla, y por lo tanto de imagen. Son hermanas. Cambiar de idioma no traduce la página: la reescribe.
  7. El acceso es un umbral, no un muro. Los textos restringidos no se esconden: se sellan. La cifra queda a la vista, pública e ilegible, y la llave se entrega a mano. Un texto cerrado sigue siendo parte visible del archivo.

Materia

  • Negro #08070b para la sala; hueso #e8e3da para la letra; púrpura #7a3fd6 y su luz #c9a6ff para la obra 001.
  • Letra: una romana de alto contraste para la escritura (Cormorant Garamond), una monoespaciada para todo lo que no es obra — folios, fechas, avisos. El aparato nunca se disfraza de literatura.
  • Modo papel: la sala se apaga y queda la página. Leer largo en negro cansa; un archivo de escritura tiene que dejarse leer.
  • Impresión: cada texto está compuesto para imprimirse en negro sobre blanco, sin la forma. La escritura tiene que sobrevivir sin el dibujo.

Fases

  1. Fase 0 · base sólida — hecha

    Sitio estático en GitHub Pages, sin dependencias, sin analítica, sin cookies. Canvas 2D. Un compilador de cuarenta líneas (tools/build.py) aplica la tabla de reglas a los .md y escribe el análisis en el HTML. Cámara sellada. Lector que da forma a cualquier texto del archivo sin página propia.

  2. Fase 1 · el taller

    Salas en WebGL con three.js (la primera ya está en pie). Estudios en Processing para lo que la pantalla no da: grabado, plotter, gran formato, tinta. SuperCollider para la voz — piezas cortas, nunca automáticas, nunca en bucle. Bocetos publicados en OpenProcessing como cuaderno abierto.

  3. Fase 2 · dinámico

    Acceso por persona y revocable: invitación por enlace firmado, una función de borde (Cloudflare Pages Functions o equivalente) que entrega el texto sólo a quien fue invitado, y la cifra actual como respaldo. Versiones del texto — el archivo muestra sus tachaduras. Notas privadas de lectura.

  4. Fase 3 · la edición

    Serie numerada: cada obra existe como página, como impresión y como sonido. Lo impreso se tira del mismo código que lo pintado en pantalla, con la misma semilla: una sola regla, tres soportes.

Lo que este sitio no va a hacer

  • Ninguna animación en bucle infinito.
  • Ninguna imagen de banco, ninguna ilustración del texto: sólo reglas.
  • Ningún sonido que empiece solo.
  • Ninguna analítica, ningún rastreador, ningún aviso de cookies.
  • Ningún texto de relleno: si un hueco no tiene texto, se queda vacío.

Protocolo de evolución

  1. El texto entra como .md en docs/. Es la única fuente.
  2. python tools/build.py parte el texto en oraciones, las clasifica y escribe el resultado en el HTML.
  3. Si el texto pide forma propia, nace una carpeta en docs/obra/ con su sketch. Si no, el lector le da forma con las reglas comunes.
  4. Toda obra nueva que necesite un gesto nuevo añade una regla a este documento y sube la versión del cuaderno: R1 → R2. El sitio evoluciona por reglas, no por estilos.

Poetics · version R1 · 2026

AÚN

Aún is Spanish for still, yet: that which has not ceased. The archive takes its name from that, because its subject is persistence — your voice that has not ceased since then — and because a site for writing should behave like memory rather than like a display case: accumulate, erase badly, leave residue.

The proposal in one sentence: an archive of writings where each text generates its own form through public, deterministic rules. The form does not illustrate the text. It reads it. And because the rule is public, the work can be argued with, refuted and continued — which is what separates it from generative decoration.

The rules

The whole system fits in seven rules. They are numbered because they will change: the current version of the rulebook is R1, and every new work may add or correct one.

  1. The text is the seed. The drawing is computed from the text itself: a hash of its letters feeds the random generator. The same text always yields the same image. No per-session randomness, no “regenerate until it looks nice”.
  2. The page is the data. The drawing reads no database and no JSON: it reads the DOM of the page holding it. If the text changes, the form changes. If the text goes, the form goes. There are never two truths.
  3. Nothing loops. Time is material: each work deposits itself over some thirty seconds and then stops. An infinite loop is a false promise of life. What there is here is sediment.
  4. Negation erases, addition deposits. Syntax governs form. A sentence that negates is drawn as subtraction; one that adds, as deposit. The table of correspondences is below, and it is the revisable part of the system.
  5. One work, one colour. Room black, bone white for the letter, and a single chromatic accent per text, taken from its own matter — in work 001, the purple of the hair. Two accents would be decoration.
  6. Two languages, two sisters. Spanish and English are not the same work translated: they take different seeds, therefore different images. They are sisters. Switching language does not translate the page: it rewrites it.
  7. Access is a threshold, not a wall. Restricted texts are not hidden: they are sealed. The cipher stays in plain sight, public and unreadable, and the key is handed over in person. A closed text remains a visible part of the archive.

Matter

  • Black #08070b for the room; bone #e8e3da for the letter; purple #7a3fd6 and its light #c9a6ff for work 001.
  • Type: a high-contrast roman for the writing (Cormorant Garamond), a monospace for everything that is not the work — folios, dates, notices. The apparatus never disguises itself as literature.
  • Paper mode: the room goes out and the page remains. Long reading on black is tiring; an archive of writing has to let itself be read.
  • Print: every text is set to print black on white, without the form. The writing has to survive without the drawing.

Phases

  1. Phase 0 · solid base — done

    Static site on GitHub Pages: no dependencies, no analytics, no cookies. Canvas 2D. A forty-line compiler (tools/build.py) applies the rule table to the .md files and writes the analysis into the HTML. Sealed chamber. A reader that gives form to any text in the archive without a page of its own.

  2. Phase 1 · the workshop

    WebGL rooms with three.js (the first one already stands). Studies in Processing for what the screen cannot give: engraving, plotter, large format, ink. SuperCollider for the voice — short pieces, never automatic, never looped. Sketches published on OpenProcessing as an open notebook.

  3. Phase 2 · dynamic

    Per-person, revocable access: invitation by signed link, an edge function (Cloudflare Pages Functions or equivalent) that hands the text only to the invited, with today's cipher as fallback. Versions of a text — the archive shows its crossings-out. Private reading notes.

  4. Phase 3 · the edition

    A numbered series: each work exists as page, as print and as sound. The print is pulled from the same code as the screen, with the same seed: one rule, three supports.

What this site will not do

  • No infinite loops.
  • No stock imagery, no illustration of the text: rules only.
  • No sound that starts by itself.
  • No analytics, no trackers, no cookie notice.
  • No filler text: an empty slot stays empty.

Protocol of evolution

  1. A text enters as .md in docs/. That is the only source.
  2. python tools/build.py splits it into sentences, classifies them and writes the result into the HTML.
  3. If the text asks for a form of its own, a folder is born in docs/obra/ with its sketch. If not, the reader gives it form with the common rules.
  4. Any new work that needs a new gesture adds a rule to this document and bumps the rulebook: R1 → R2. The site evolves by rules, not by styles.
